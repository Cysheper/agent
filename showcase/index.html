Agent Project

一个基于 OpenAI 兼容接口的 LLM Agent 原型。服务收到消息后循环请求模型，解析 JSON 指令，执行注册工具，并通过 SSE 把过程一点点吐回来。

Python 3.12+uvFastAPISSE 流式JSON 事件循环工具注册器

三句话概括

模型只输出 JSON

每轮返回 print、tool_use、end_task，服务据此决定说什么、调哪个工具、什么时候停。

工具靠装饰器注册

@tool 把函数收进注册表，函数 docstring 直接被拼进系统提示词，模型看到的就是工具说明书。

上下文会自己瘦身

超过 context_length 就调模型做摘要，过长的工具结果也会被压成一句话。

一次对话怎么走

  1. 用户消息经 Message 包装，加上通道标记后写进上下文和 SQLite。
  2. 带系统提示词请求模型，要求 json_object 格式输出。
  3. 解析 JSON：print 直接产出 Agent 消息，tool_use 逐个执行工具。
  4. 工具结果作为 system 消息回写上下文，继续下一轮，直到 end_task 为真。
  5. 全过程中每条消息都以 data: 事件流式返回。

模型输出长这样

{
  "print": ["我先查一下现在几点。"],
  "tool_use": { "shell": { "cmd": ["date"] } },
  "end_task": true
}

HTTP 接口

路由用途
GET /健康检查，返回 {"status":"Ok"}
GET /qq?content=...按 QQ 通道标记输入，返回 text/event-stream
GET /qq_offical?user_name=...&content=...同上，额外接收昵称参数
 

curl -N --get 'http://127.0.0.1:3000/qq' \
  --data-urlencode 'content=现在几点了？'

data: 我先查一下。
data: [ToolUse] tool_name=shell args={'cmd': ['date']} returns={'stdout': '...', 'returncode': 0}

内置工具

工具说明
shell(cmd)执行本机命令，返回 stdout / stderr / returncode，是主力工具
weather(city)占位示例，固定返回晴天
web_search(query, count)调用 DeepSeek 搜索接口，需要 API Key
web_fetch(url)抓网页正文，返回标题与内容
get_balance()查询账户余额
memory_get / memory_add实验性记忆接口，依赖仓库外部的 ./mem 程序

模块划分

main.py

FastAPI 入口，三个 GET 路由，端口读 agent_port。

src/

Agent 循环、LLM 封装、上下文压缩、数据结构、输出通道。

tools/

shell、weather、搜索、抓取、余额、记忆，全靠 @tool 注册。

prompt/

fish.md + agent.md + tools.md 拼成系统提示词。

IO/

OneBot HTTP 版 QQ 封装与官方 botpy 通道。

memory/ utils/

实验性记忆实现与队列工具。

已知限制

shell 能执行服务进程可访问的本机命令，只适合在可信环境里跑，不能直接暴露给不可信用户。

  • 每个 Agent 只有一份上下文，并发请求会共享状态，没有会话隔离与持久化。
  • 没有停止任务接口，QQ Bot 生命周期也还没接上，botpy 相关代码仍是注释状态。
  • memory 工具依赖仓库外部的 ./mem 可执行文件，未配置时不可用。
